# 評価：ハッカソンの審査員（Claude チームのエンジニア、医療の知識なし）

対象：デモ動画 3分（台本 第5版の試作、2:59）。資料 `recordings/eval-story-v5/00-materials.md` と scene0〜11.png の12枚を見て評価した。

## 1. 心に残ったこと

「最初の負け試合が、実は"自分が楽勝したせいで生まれた敵"だった、という種明かしがよくできていた。病院の薬剤師が自分の研究テーマ（選択圧）をそのままゲームのルールにしていて、Claude はステージを作ったあとボットで遊ばせて『切り札だけで勝てちゃう』を自分で見つけて直していた」——同僚にはこう話すと思う。1回目と2回目の並べ比べ（切り札 100% → 3%、効かない細菌 12% → 0%）は、医療を知らない自分でも一目で分かった。

## 2. 作者と、作った理由

- 受け取ったこと：病院で10年以上、感染症の治療に関わってきた薬剤師が、「薬の選び方の結果は何年も先にしか返ってこないので、現場で学ぶ機会が少ない」という問題を、数分で失敗できるゲームにした。最後に「一人で教えられる人数には限りがある」と言うので、教える人数を増やすための道具だと分かる。
- 経歴の出し方：おおむね「身元を明かして、内容の確かさを判断してもらう」ものに見えた。理由は、名乗りのすぐ後に「だからゲームにした」と動機に戻っていくこと、シーン9で「値は私が公的な文書で確かめた」と、経歴が"確かめる責任"の裏付けとして使われていること。
- ただし、カードの3行目（論文11本・英文8本・招待講演・賞の名前）は、ナレーションでは触れず文字だけで出るので、そこだけは履歴書っぽく感じた。「感染制御専門薬剤師」「Young Challenger Award」「臨床薬剤疫学」は、自分には何のことか知らない（どれくらいすごいのか判断できない）。

## 4. 冒頭（0:00〜0:40）

- 引き込まれた。声のない負け試合 → 年間1,000万人・がんを超える、で「これはゲームの話ではなく大きな社会問題の話だ」と最初の20秒で切り替わる。シーン0は単体ではよく分からないが、シーン6で回収されるので「分からないまま見せる」が正しく機能している。
- 問題の大きさは十分伝わった。棒グラフは医療の知識がなくても読める。
- 一方、シーン2（21.5秒）はやや長い。「正しく使う」「切り札が続きがち」「何年も先に返る」「学ぶ機会が少ない」の4つが続き、図の下の「学ぶ機会は少ない」は字幕と同じ文が2回出る。ここは15秒前後に縮められそう。

## 5. 名乗り（0:40〜1:00）

- 長さ（約12秒が経歴）はぎりぎり許せる範囲。ナレーションは「薬剤師・博士号・専門資格・10年以上」だけで、自慢というより「この人なら薬の値を確かめられる」という資格の提示として受け取った。
- 小さな丸い写真は控えめで良い。顔が出ることで「本物の現場の人が作った」という信頼にはつながった。
- 気になったのは、カードの3行目（論文・招待講演・賞）。読めないほど小さいのに情報が多く、「載せるだけ載せた」印象が少し出る。資格の意味も自分には分からないので、カードは1〜2行に絞り、「感染症の薬の使い方を病院で指導する専門の薬剤師」のように、知らない人に役割が伝わる言い方のほうが効く。
- 「何年も先の結果を数分で、安全に失敗しながら学べるゲームにしました」は、この動画の要約として最良の一文。タイトル画面と重なっていて良い。

## 6. Claude の活用（シーン8・9）

- 見えたこと：先生が地域と教えたいことを入れる → Claude が地域のデータを読み、ステージを作り、ボットのシミュレーションを回し、「切り札だけで勝ててしまう割合 27%（上限 30% に近い）」を自分で見つけて敵を増やし、17% まで下げて提出する → 最後は専門家が承認して QR で配る。さらに「数値は公開データのまま、Claude には作らせない」。これはツールを使って自分の出力を検証するエージェントの使い方で、Claude チームの人間としては一番うれしい場面。
- 「Claude だからできた」と言えるか：半分は言える。「試して、基準を外れたら自分で直し、確かめ直す」ループは、長い作業を自律的にこなせるモデルとツール利用があってこそ。ただ動画では、どのツール（データ取得・シミュレーション）を Claude に渡したのか、何回試したのか（工程の図の 1〜5 の意味）が読み取れず、「普通の生成 AI でステージ JSON を作った」と区別がつきにくい。スキル（知識のメモ）で試行錯誤が減った比較は、まさに差別化の材料なのに一瞬で終わる。
- 等速で見たい場面：
  1. シーン8の「27% → 敵を増やす → 17%」の瞬間（いまは ×2.4〜×22 の切り替えの中で流れる）。Claude の作業記録の一行（例：「切り札だけで 27%。上限に近いので敵を増やす」）を大きく1つ見せてほしい。
  2. シーン9のスキルあり・なしの比較（提出までのシミュレーション回数・時間・費用）。

## 7. 4つの観点の見込み

| 観点 | 見込み | 理由 |
|---|---|---|
| インパクト（30%） | 強い | 年間1,000万人という問題の大きさ、教える人数の限界という現場の課題、使う場面（勉強会・実習・講義）まで具体的 |
| デモ（25%） | ふつう〜強い | 負け → 種明かし → やり直しの構成はとても良い。ただゲーム画面は文字が細かく、早送りが多く、勝つ瞬間の絵が弱い |
| Claude の活用（25%） | ふつう | 自分で試して直すエージェントの使い方と「数値は作らせない」線引きは良い。速すぎ・小さすぎで、審査員に「Claude ならでは」が伝わり切らない |
| 深さと実行力（20%） | 強い | 公開データ（JANIS）からの耐性率、公的文書で確かめた値の一覧、スキルあり・なしの評価、教員モードまで作り込んでいる。現場の専門家が一人で作った量として説得力がある |

## 8. 直すとよい点（重い順）

1. **シーン8の Claude の見せ場を、等速・大きな文字で1つに絞る。**いまは速度が4回変わり、作業記録も工程の図も小さい。「Claude がボットで試す → 切り札だけで 27% 勝てる → 敵を増やす → 17%」を、作業記録の1行を拡大して2〜3秒は等速で見せる。ナレーションに「データの取得とシミュレーションを道具として渡し」など、何を任せたかを短く足す。シーン9のスキル比較も、1つの数字（例：189秒 → 139秒、シミュレーション回数が減った）だけ大きく見せる。時間は、シーン2（21.5秒）を約16秒に縮め（図の下の「学ぶ機会は少ない」の重複を消す）、シーン3の経歴カードを2行にして約2秒縮めて作る（計 約7〜8秒）。
2. **シーン7の勝つ瞬間を見せる。**2:03.5 のコマは黒い画面に字幕だけで、「守り切った！」の盤面が映っていない。シーン0・6の「膀胱が破られた」と対になる絵（膀胱が残っている盤面）を1.5〜2秒、等倍で入れる。時間は並べ比べの表示（3.5秒）を少し詰めるか、×39 の早送りを短くして作る（シーンの長さは変えない）。
3. **ゲーム画面に重ねる専門用語を減らす。**シーン5上のテロップ（グラム染色・感受性・JANIS）、シーン7の「CTRX・CMZ」、名乗りカードの資格名・賞の名前は、医療を知らない審査員には読めず、画面の情報を増やすだけ。シーン5のテロップは「近づくほど、細菌の正体と効く薬が分かる」程度の一行に、シーン7は「この細菌に合う薬（セフメタゾール）」のように略号を外す。時間は変わらない。
