## プロジェクト概要（解決する課題と、誰のためのものか）

薬学生・新人の医療者が、抗菌薬の選び方を学ぶタワーディフェンスです。教える人（薬剤師・教員）は、Claude に自分の地域の公開データからステージを作らせられます。

対策をとらなければ、2050年に薬剤耐性による死亡は年間1,000万人になり、がんを超えるという試算があります。抗菌薬（いわゆる抗生物質）は、薬ごとに効く細菌が違います。はじめは原因の細菌が分からないので、ほとんどの細菌に効く「切り札」が選ばれやすい。でも薬を使うと、効く細菌は倒れ、薬が効かない細菌だけが残って増えます（選択圧）。耐性を防ぐ要は抗菌薬の適正使用ですが、薬学生や新人の医療者がそれを実践的に学ぶ機会は少ないのが現状です。

私は病院で抗菌薬の使い方を支える AST（抗菌薬適正使用支援チーム）の薬剤師です（薬剤師・博士（薬学）・感染制御専門薬剤師。経歴：researchmap https://researchmap.jp/ph1125ks/ ／ LinkedIn https://www.linkedin.com/in/ph1125ks/ ）。「切り札を使えば、いまは楽に勝てる。でも、そのつけは未来に回る」を、説明ではなく体験で伝えるために、抗菌薬のタワーディフェンス「センタクアツ」を作りました。

学ぶ人は、国の公開データ（JANIS）の耐性率から始まるステージ1「いま」で、近づくほど分かってくる細菌の手がかり（顕微鏡で見た色と形、細菌の名前、効く薬。実際の検査の結果が時間差で届くのと同じ）をもとに抗菌薬を選びます。ステージ2「2050年」は、ステージ1の使い方が続いたとみなした耐性率で始まり、切り札を乱用すると、自分が残した薬が効かない細菌に負けます。自然耐性・吸収率・投与回数・供給制限・薬価も、厚生労働省の手引きや薬価基準に沿って入れました。ブラウザだけで遊べます。医療を知らない人のために、しくみを絵で説明する「はじめての人へ」のページも作り、立場の違う10人の評価役（中学生〜72歳、保護者、外国出身の人など）で伝わるかを確かめて直しました。抗菌薬を、なぜ適切に使わなければいけないのか。それを知ることは、抗菌薬を処方された人が、自分の薬の意味を理解することにもつながります。

教える人（薬剤師・教員）は、教員モードで地域と教えたいことを入れるだけで、Claude にその地域のデータに合ったステージを作らせられます。いま作ってあるのは膀胱炎（尿路）だけですが、ステージに出てくる菌はその検体から分離される菌の割合を公開データから読んで選ばれるので、肺炎など別の感染症にも、その検体の菌と割合を選び直して広げられる形にしています（今回の範囲は尿路だけ）。

**誰のためか**：病院実務実習の薬学生、院内の新人研修を受ける医療者、大学・専門学校で抗菌薬を学ぶ学生と、それを教える薬剤師・教員。

**使い続ける場面**：院内の新人・若手の勉強会（作者は病院の AST の薬剤師）、病院の実務実習の薬学生、大学の講義・実習。地域や対象が変わっても、教員モードでその地域の公開データからステージを作り直せるので、使い続けられます。【作者】時期や場所を足すなら、公開してよい範囲で

## Claude の利用

要点：ゲームの中では、教員モードの Claude（claude-opus-5-5）がステージを設計し、自分でシミュレーションして直してから出します（数値は作らせません）。開発は Claude Code を中心に、スキル2・サブエージェント3・評価役10人・フック2を目的ごとに使い分け、スキルの効果をあり・なしで測りました。

### ゲームの中の Claude：教員モード

地域・対象・教えたいこと（例：「第3世代セフェムが効かない大腸菌に、カルバペネムを使わずに勝つ経験をさせたい」）を入れると、Claude（claude-opus-5-5）がステージを設計します。Anthropic TypeScript SDK のツールランナーで、5つのツールを持たせました：地域の公開データを読む、使える薬・菌・見本を読む、4つのボット（適正・乱用・ランダム・何もしない）で各60回シミュレーションする、規則で検査する、提出する（別の乱数の種で各100回確かめ直す）。

Claude は「設計 → シミュレーション → 直す」を自分で回します。本番では、1回目で合格の目安をすべて満たしたのに、「乱用ボットの2050年の勝率 27% は上限 30% に近い」と自分で判断し、敵の波を増やして 17% にしてから提出しました（約2分・約0.5ドル）。この記録は API キーなしで再生できます（上の replay.html）。

**Claude に作らせないもの**：感受性の数値は公開データのままで、Claude はツールで読むだけです。薬の性質と薬価は公的な文書から。Claude が作ったステージは下書きで、専門家が確かめて承認するまで学生には届きません。このゲームの中の Claude はステージを作る役だけで、学生と会話せず、診療の助言もしません（教育用のシミュレーションで、実際の診療の判断には使えないことを、画面と README に書いています）。プログラムを書けない教員でも、自分の地域のデータで教材を作れることが、この機能の目的です。

### Claude Code での開発の感想等（短い版。273字）

フォームに「感想」の欄があればこれを貼る。長い版は下の「開発の中心の Claude Code」。

初日に Claude Code から質問してもらい、自分が当たり前と思っていた臨床の知識（自然耐性、内服薬の吸収率、切り札が選ばれやすい理由）を言葉にしてから作り始めました。教え方の勘所をスキルに書いて渡すと、教員モードの Claude の試行錯誤が減り、時間と費用が約3割少なくなったことを、あり・なしで動かして数字で確かめられたのが印象的でした。医学データの照合はサブエージェントに、秘密の流出を止めるのはフックに任せ、値はすべて私が公的な文書と照らしました。一人では作れなかった教材が1週間で形になり、ハッカソンのあとも現場で使い続けます。

### 開発の中心の Claude Code

- **企画**：初日に Claude Code が作者に質問して、作者が当たり前と思っていること（自然耐性・内服薬の吸収率・切り札が選ばれやすい理由）を言葉にし、作らないこと（SPEC.md 11）と、できたと言える条件（SPEC.md 12）を決めてから作り始めた
- **スキル**：ステージ設計の知識（stage-design）を、開発中の Claude Code と教員モードの Claude が同じ本文で使う。公開データの取り込み直しの手順（janis-import）
- **サブエージェント**：医学データを公開データの元の表と照合する data-auditor（読み取り専用）、ボットでゲームバランスを比べる balance-tester、アプリ内ブラウザで試遊する playtester
- **評価役**：医療を知らない人にも伝わるかを、立場の違う10人の評価役（中学生〜72歳、保護者、外国出身の人、審査員など）をサブエージェントで立てて確かめ、ゲーム・「はじめての人へ」・動画の台本を直した。台本は5人の評価役と初見の読み手役3人で版を比べ、頭に入らない版を数で見つけて組み直した（docs/eval/）
- **フック**：コミット前に API キーなどの秘密を探して止める。エンジンやデータを編集したときにエンジンのテストを動かす
- **評価**：スキルの効果を、本番と同じ入力で教員モードをスキルあり・なしで各3回動かして比べた（変えたのはスキルの有無だけ）。どちらも提出まで行けたが、スキルなしは3回とも規則の検査で止まり、1回目のシミュレーションで合格したのは0回。スキルありは規則の誤り0回・1回目で合格2回で、時間と費用は約3割少なかった（平均 139秒・0.63ドル 対 189秒・0.90ドル）
