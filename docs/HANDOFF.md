## 3. 決まっていて変えないこと

- **作者の方針**：医学的な値は、できるだけ作者の感覚ではなく公的な文書に沿って決める。文書で決まらないものは、選択肢と根拠を示して作者に聞く。値を変えたら出典（文書名・版・ページ）を書く
- **耐性化の速さ**（2026-11-03、作者の方針）：公的資料から採ったと言えるようにする。極端にしない（臨床では感性率 80% 未満だとエンピリックに使いにくく、耐性率 50% でも大問題）。2050年までの上がり方は、NAOR 2024 の実測の最速値を上限にする（ゲームの菌×薬の中で最速の組。いまは肺炎桿菌の CAZ、年 0.144。個人の意見でなく現実の数値を採る）。RAND の「15年で100%」は使わない
- **使わない薬の耐性**（2026-11-03、作者の判断）：下げるのは2050年への引き継ぎだけで、ステージ1の中では下げない。上限は NAOR 2024 の実測の下がり方
- **系統の偏りの倍率**（2026-11-03、作者の判断）：考え方は AHI。式と係数はゲームの決めごとで、文献の確認や作者の研究の式には合わせない（結果画面の「偏りの指標」の式とは別）
- **偏りの指標**（2026-11-04、作者の指定）：結果画面の「系統の使い分け（AHI）」は AHI ＝ 1 −｛n /［2 ×（n − 1）］｝× Σ｜ai − bi｜。n は手札にある系統の数、ai は 1/n、bi は使用日数の割合（%DOT）（`src/engine/results.ts` の `ahi`）
- **TAZ/PIPC は供給制限の候補に入れない**（2026-11-04、作者が Claude の判断を確認）。入れると、適正ボットがカルバペネム系でつなぐようになる
- **耐性の進み方**（2026-11-03、作者の判断）：A/B の両方をタイトル画面で選べるようにし、既定は A。録画も A で撮る。ゲームとしての質は B、現実に即しているのは A
- **医療費**（2026-11-03、作者の判断）：現実の薬価基準による薬価方式。広くて安い内服 LVFX が選びやすいのは、不適正使用につながる現実の特徴。高くても ABPC を選ぶべき場面もある
- **言葉**（2026-11-03、作者の方針）：ゲームなので、画面と台本で「患者・症例・病棟」の語を使わない（倫理的な配慮。`tests/stages.test.ts` がステージの文を検査する）。未来ステージは「2050年」と呼ぶ
- **偏り**：必要なところにバランスよく使うことを大切にする。理想は、最適な薬を選んでいれば系統がそろうこと（いまは届いていない）
- **ゲームの中の Claude** は、教員モードでステージを作る役だけ。学生と会話する機能は作らない
- **用法**：手引きの治療例の表に合わせる（国の資料を学会のガイドより優先する。2026-11-03 作者の方針）。AMK だけは作者の判断で JAID/JSC 2023 Ⅺ-E。手引きに表がない IPM/CS・CTX は JAID/JSC。**カードには用量を出さない**（投与間隔と待ち時間だけ）
- **優先して使う順**：WHO の AWaRe（Access → Watch → Reserve）。同じ群ではカルバペネム系とキノロン系を後に回す。同順位はカバー率の低いほう
- **連動**：ESBL と CRE（1章の表）。菌ごとの木にして、全体の耐性率は表の値を保つ。耐性モデルで値を変えたら、必ず下限をかけ直す（エンジンの `withModel` と `extrapolate` が行う）
- **効く確率**は JANIS の S のみ。自然耐性は EUCAST Expected Resistant Phenotypes v1.2。腸球菌の MEPM と IPM/CS は「効かない扱い」と表示する（自然耐性でも獲得耐性でもない）。腸球菌の TAZ/PIPC は ABPC で代用して効く扱い
- **台本**：シーン3の「MEPM を連打して楽勝」は、ボットではなく録画用の操作シナリオで作る。シーン0の字幕は「抗菌薬が、効かなくなる。」

## 5. 開発の仕組みと、つまずきやすい点

- **公開**：main に push すると `.github/workflows/pages.yml` が動く（`npm ci` → `npm test` → `npm run build` → Pages）。`data/raw/` はリポジトリにないので、CI では `data:verify` を動かさない。公開と同じサブパス（/Built-with-Claude-Japan-2026/）で確かめるときは、`npm run build` のあと `.claude/launch.json` の "pages-preview"（ポート 4173）。Actions の結果は `gh run list --workflow pages.yml` で見られる
- **GitHub 側の状態を話す前に** `git fetch` と `git status -sb` で、push 済みかどうかを確かめる
- **フック**（`.claude/settings.json`）
  - コミット前：`git commit` を含むコマンドで、API キーなどの文字列を探して止める
  - 編集後：`src/engine/`・`tests/`・`data/` を編集すると単体テストが走る。複数の編集の途中でも失敗を知らせてくるので、最後まで編集してから判断する（`src/game/` は対象外。`npm run typecheck` と `npm run build` で確かめる）
- **サブエージェント**：`data-auditor`（データや出典、画面の医学的な言い回しを変えたら）、`balance-tester`（シミュレーションの比較）、`playtester`（アプリ内ブラウザでの試遊）
- **サブエージェントを並べて動かすとき**：`balance-tester` と `playtester` はエンジンと画面をそのまま使う。動いている間に `src/` や `data/rules.json` を書き換えると、比較の数値が混ざったり、画面が再読み込みされたりする。変更はリポジトリの写し（スクラッチパッドに rsync、`node_modules` はリンク）で確かめ、終わってから本体に入れた
- **アプリ内ブラウザの画面が隠れていると、ゲームの時計がほぼ止まる**（描画のたびに進めているため）。確かめるときは、コンソールで `window.sentakuatsu.fastForward(秒)` や `window.sentakuatsu.press("start")` などを使う。`?auto=appropriate`（適正ボット）・`?auto=broad`（乱用ボット）で自動で遊ばせられる。スクリーンショットは1枚遅れて写ることがあるので、2回撮る。座標でのクリックは、直前にスクリーンショットを撮っていないと外れる（`find` で要素を探すほうが確実）
- **最初のステージは止めた状態で始まる**（`?auto=` のときを除く）。手で確かめるときは「再開」かスペースを押す
- **画面の URL**：`?stage=`・`?model=A|B|none`・`?cost=yakka|abstract`・`?budget=はじめ,1日ごと[,上限]`・`?seed=`・`?region=`・`?auto=`・`?r=`（盤面の解像度。1080p の録画は `?r=1.5`）・`?debug`（ステージ名や耐性モデルの名前などの開発用の表示。`?debug` のときだけ出る）
- **タイトル画面の耐性モデルの選択**はブラウザ（localStorage `sentakuatsu.model`）に残る。試すときに前の選択が残っていることがあるので、`?model=` で固定するか、タイトル画面で選び直す
- **開発サーバー**：`.claude/launch.json` の "game"（ポート 5173。使われていると 5174 になる）
- **医学資料の置き場所**：追加フォルダ（Cowork）の `04_医学資料`（索引は `00_README.md`）。ASC スコアの論文は `08_ASCスコア/`、NAOR 2024 は `07_NAOR2024/`。本文はリポジトリにコピー・引用しない。作者が新しい資料を `_inbox/` に置いたら、読んでから番号付きのフォルダに日付付きの名前で移す
- **兵士と細菌の絵**（`src/game/pixel/`）：コードで書いたドット絵。`engine.js` が仕組み（行の文字列 → ドット、色の段、輪郭、点描、切り抜き）、`styles/c32.js` が作風 C（9系統の兵士の待機2コマ・攻撃2コマ、細菌5種の2コマ、べん毛のない絵 `bare`）。どちらも JS で、型は横の `.d.ts`。盤面では `BoardScene.makeTextures` で、薬×コマ×濃さ8段と、菌×2コマ×べん毛の有無を等倍のテクスチャにし、ぼかさずに拡大する（NEAREST）。カードと遊び方の絵は `soldierImg` で整数倍の PNG にして `<img class="px">` で出す（カードは上半身の切り抜き `cardCrop`）。系統を足したら、`soldiers.ts` の `CLASS_LOOKS` と作風の絵の両方に足す（`tests/pixel.test.ts` が全部の薬のコマ・紋章・台・べん毛なしの絵を確かめる）。レーンの兵士の絵は菌より下の層（深さ 8）、名札だけ菌の札より上の層（深さ 30）。ほかの4作風と見本帳の元ファイルは、リポジトリの外（作者の手元）に控えてある
- **バージョン**：Phaser は 3.90.0 に固定。TypeScript 7.0、Vite 8、Vitest 5。本番ビルドは約 1.4MB（Phaser が大半）
- **EUCAST のサイト**はスクリプトからの直接ダウンロードを 403 で拒否する。回避はしない
- **日本語を含む一括置換**：シェルのヒアドキュメントに Python を書くと、日本語が化けて失敗したことがある。スクラッチパッドに `.py` を書いて実行するほうが安全。`json.dumps` で JSON を書き直すと整形が全部変わるので、行を差し替える。JSON を行で書き換えたら、カンマの抜けや重なりに気をつける（テストが全部落ちる）
- **データを足したら** `npm run data:build` で `data/generated/` を作り直す（薬価がないとテストが落ちる）。手順はスキル `janis-import`
- **数値の集計**：`npm run sim` は平均。DEVLOG の耐性率の表は中央値。表に書くときはどちらかを明記する。データを変えると、値を直接確かめているテスト（ASC、ボットの選ぶ薬、供給制限の枚数など）も直す
- **シミュレーションの補助**：`runScenario`（`src/engine/simulate.ts`）の戻り値に、ステージ1の始めと終わりの耐性率（`present.resistanceStart`・`resistanceEnd`）と、2050年の開始時の表（`futureStart`）がある。`npx tsx` でスクリプトから呼べる。ルールを書き換えずに試すときは `loadGameData({ rules: { board: { ...base.rules.board, revealSusceptibilityBelow: 0.6667 } } })` のように上書きする（上書きは最上位の項目ごと）
- **引き継ぎの呼び方**：`model.carryOver(data, start, end, years, usedDrugsOf(present.activeDays))`。最後の引数を渡さないと、使わなかった薬を下げない
- **代用の組をつなぐ設定**（`resistance.A.sharedSelection`）は、`susceptibility.proxies` の useJanis の組と一致しないと、読み込みのときに止まる（`src/engine/data.ts`）
