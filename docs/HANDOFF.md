## 3. 決まっていて変えないこと

- **作者の方針**：医学的な値は、できるだけ作者の感覚ではなく公的な文書に沿って決める。文書で決まらないものは作者に聞く（選択肢と根拠を示して）。値を変えたら出典（文書名・版・ページ）を書く
- **ゲームの中の Claude** は教員モードでステージを作る役だけ。学生と会話する機能は作らない（禁止例の「医療アドバイスを行う AI」「AI for Education チャットボット」に当たらないため）
- **用法**：手引きの治療例の表に合わせる。AMK だけ JAID/JSC 感染症治療ガイド2023 Ⅺ-E（1回15mg/kg・1日1回、体重60kg で 900mg。国内の電子添文の範囲の外であることも出典に書いてある）
- **優先して使う順**：WHO の AWaRe（Access → Watch → Reserve）。同じ群ではカルバペネム系とキノロン系を後に回す。同順位はカバー率の低いほう（`src/engine/stewardship.ts`）
- **ESBL の連動**：腸内細菌目で CTRX 耐性の個体は ABPC・CEZ・経口第3世代セフェム・CFPM にも耐性。CMZ と MEPM は連動させない。全体の耐性率はデータを保つ（CFPM と経口第3世代は CTRX が下限）
- **効く確率**は JANIS の S のみ。自然耐性は EUCAST Expected Resistant Phenotypes v1.2 に沿う。尿中移行の係数は全薬 1.0
- **台本**：シーン3の「MEPM を連打して楽勝」は、ボットではなく録画用の操作シナリオで作る。乱用ボットはキノロンも温存の対象になったため、MEPM が待ち時間のあいだは LVFX を使い、膀胱の残りが 48% まで落ちる

## 5. 開発の仕組みと、つまずきやすい点

- **フック**（`.claude/settings.json`）
  - コミット前：`git commit` を含むコマンドで、API キーなどの文字列を探して止める
  - 編集後：`src/engine/`・`tests/`・`data/` を編集すると単体テストが走る。**複数の編集の途中**（import を足す前など）でも失敗を知らせてくるので、最後まで編集してから判断する
- **サブエージェント**（`.claude/agents/`）
  - `data-auditor`：データや出典を変えたら走らせる。これまで4回で毎回、出典の書き方の誤りや言い過ぎを見つけた
  - `balance-tester`：シミュレーションの比較。`playtester`：アプリ内ブラウザでの試遊（`.claude/launch.json` が要る）
- **スキル**：`janis-import`（年報や薬価が新しくなったときの取り込み手順）
- **医学資料の置き場所**：GitHub に入れない資料（手引き4冊、JAID/JSC ガイド、EUCAST 3文書、IF、電子添文、それぞれのテキスト版）は、追加フォルダ（Cowork）の `04_医学資料`。公開データの元ファイルの控えは `05_公開データ`。索引は各フォルダの `00_README.md`（ページ番号のずれの注意もある）。新しいセッションでは、このフォルダを追加フォルダとして足す
- **本文を写さない**：追加フォルダの文書の本文はリポジトリにコピー・引用しない（CLAUDE.md）。書名・版・ページと数値だけ
- **バージョン**：Phaser は v4 が最新だが、仕様どおり **3.90.0 に固定**。TypeScript は 7.0（`.ts` の import に `allowImportingTsExtensions` が必要）、Vite 8、Vitest 5
- **EUCAST のサイト**はスクリプトからの直接ダウンロードを 403 で拒否する。回避はしない
- `exceljs` の脆弱性警告は、手元で公的な Excel を読むだけの開発用なので許容している
