## 3. 決まっていて変えないこと

- **作者の方針**：医学的な値は、できるだけ作者の感覚ではなく公的な文書に沿って決める。文書で決まらないものは作者に聞く（選択肢と根拠を示して）。値を変えたら出典（文書名・版・ページ）を書く
- **ゲームの中の Claude** は教員モードでステージを作る役だけ。学生と会話する機能は作らない
- **用法**：手引きの治療例の表に合わせる。AMK だけ JAID/JSC 2023 Ⅺ-E。**カードには用量を出さない**（投与間隔と待ち時間だけ）
- **優先して使う順**：WHO の AWaRe（Access → Watch → Reserve）。同じ群ではカルバペネム系とキノロン系を後に回す。同順位はカバー率の低いほう
- **連動**：ESBL（CTRX → ABPC・CEZ・経口第3世代セフェム・CFPM）と CRE（MEPM → CTRX・CMZ・TAZ/PIPC。CRE は作者の確認待ち）。菌ごとの木にして、全体の耐性率は表の値を保つ。耐性モデルで値を変えたら必ず下限をかけ直す（エンジンの `withModel` がやる）
- **効く確率**は JANIS の S のみ。自然耐性は EUCAST Expected Resistant Phenotypes v1.2。腸球菌の MEPM は「効かない扱い」と表示する（自然耐性でも獲得耐性でもない）
- **台本**：シーン3の「MEPM を連打して楽勝」は、ボットではなく録画用の操作シナリオで作る

## 5. 開発の仕組みと、つまずきやすい点

- **フック**（`.claude/settings.json`）
  - コミット前：`git commit` を含むコマンドで、API キーなどの文字列を探して止める
  - 編集後：`src/engine/`・`tests/`・`data/` を編集すると単体テストが走る。複数の編集の途中でも失敗を知らせてくるので、最後まで編集してから判断する（`src/game/` は対象外。`npm run typecheck` と `npm run build` で確かめる）
- **サブエージェント**：`data-auditor`（データや出典、画面の医学的な言い回しを変えたら）、`balance-tester`（シミュレーションの比較）、`playtester`（アプリ内ブラウザでの試遊）
- **アプリ内ブラウザの画面が隠れていると、ゲームの時計がほぼ止まる**（描画のたびに進めているため）。確かめるときは、コンソールで `window.sentakuatsu.fastForward(秒)`、`window.sentakuatsu.press("start")` などを使う。`?auto=appropriate`（適正ボット）・`?auto=broad`（乱用ボット）で自動で遊ばせられる
- **画面の URL**：`?stage=`・`?model=A|B|none`・`?seed=`・`?region=`・`?auto=`・`?r=`（盤面の解像度。1080p の録画は `?r=1.5`）
- **医学資料の置き場所**：追加フォルダ（Cowork）の `04_医学資料`（索引は `00_README.md`）。本文はリポジトリにコピー・引用しない
- **バージョン**：Phaser は 3.90.0 に固定。TypeScript 7.0、Vite 8、Vitest 5。本番ビルドは約 1.3MB（Phaser が大半）
- **EUCAST のサイト**はスクリプトからの直接ダウンロードを 403 で拒否する。回避はしない
