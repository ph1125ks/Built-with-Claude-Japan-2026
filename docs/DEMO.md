## この動画で伝えること

1. **どれくらい困っているか**：抗菌薬が効かない（冒頭のテロップ）。このまま薬剤耐性が広がると、2050年には年間1,000万人が亡くなる。がんを超える、という試算がある
2. **抗菌薬を正しく使うことが大切。でも、学ぶ機会が少ない**：使い方の影響が返ってくるのは何年も先で、確かめながら学ぶ機会は多くない
3. **どう解決するか**：数分で、安全に失敗しながら学べるタワーディフェンス
4. **作ったのは誰か（身元の開示）**：博士号と感染症の専門資格を持ち、病院で10年以上、感染症の治療に携わってきた薬剤師。経歴のカードに、名前・所属・論文・招待講演・学会の賞
5. **しくみ（すべての人に。遊びながら）**：細菌の正体は近づくほど分かる。手札の薬は薬ごとに効く細菌が違い、ほとんどの細菌に効く「切り札」もある。なら切り札だけ使えばいい？ 連打すると楽勝。ところが、効く細菌は倒れ、効かない細菌だけが残って増える（選択圧。作者の研究テーマで、ゲームの名前）。そして2050年に、自分が残した細菌に負ける
6. **Claude の役割**：教える人が地域と教えたいことを入れると、Claude がその地域の公開データでステージを作り、自分で試して直す。数値は作らせない。肺炎など別の感染症にも広げられる仕組み。開発も Claude Code と一緒に行い、薬の値や耐性の速さは、作者が公的な文書と照らして確かめた
7. **これから**：これから現場に立つ人たちに届ける。いまの一手が、未来をつくる

## 収録の準備

- ゲームは乱数の種（シード）を固定して収録する。同じ操作なら毎回同じ展開になるようにする（SPEC.md「完成の定義」）
- 耐性の進み方（A：薬ごと／B：系統ごと）もURL（`?model=A` か `?model=B`）で固定して収録する。タイトル画面で選んだものはブラウザに覚えるので、固定しないと前に選んだほうで始まる
- プレイの場面は、録画用の操作シナリオ（乱用・適正）で自動再生する。手で遊ぶと尺がぶれるため
  - 乱用（`?auto=demo-abuse`）：ステージ1も2050年も、カルバペネム系（MEPM）を連打する（2026-11-06 に 2050年の手札から IPM/CS を外した）。2026-11-04 作者の判断

  - 種は **570**（`scripts/demo-seeds.ts` で選んだ。乱用はステージ1を膀胱84%で楽勝し、2050年は手札のどれも効かない菌が14%で負ける。適正はステージ1も2050年も守り切る（膀胱 100%／100%。2026-11-06 に IPM/CS を外し区間を 25/25/50 にしたあとの値。前は 12%、100%／88%）。乱用と適正で同じ種なので、やり直しでも手札がそろう）。`tests/demo.test.ts` がこの展開を確かめる。データやルールを変えてテストが落ちたら、種を選び直す

## 動画の作り方

- **第一案（自動化）**
  1. ブラウザの自動操作でプレイ画面と教員画面を録画する（Claude が用意する）
  2. 作者がこの台本を読み、シーンごとに録音する
  3. スクリプトで録画・字幕・音声をつなぎ、MP4（1920×1080）に書き出す
  4. 作者が確認し、YouTube に限定公開でアップロードして、提出フォームに貼る
- **仮の動画**：`npx tsx scripts/make-draft-video.ts` で、録画（`recordings/`）を台本の時間配分どおりに切り出して早送りし、ナレーションを字幕と声にしてつなぐ。字幕と、コードで描く絵（名乗りの場面・並べ比べ・エンドカード）は画面なしの Chrome で描いて重ねる（手元の ffmpeg には文字を描く機能がない）。動く絵は先に作っておく：試算の図は `npx tsx scripts/make-hook-chart.ts`（`recordings/hook/`）、シーン2の細菌が耐性を獲得していく絵は `npx tsx scripts/make-scene2.ts`（`recordings/scene2/`。`--at 4.8,7.6` でそのコマだけ静止画に）。どちらも1コマずつ Chrome で描いて ffmpeg でつなぐ。ゲームのドット絵（細菌・兵士・盾・膀胱・床）は `scripts/lib/pixel-art.ts` で Node から PNG にして使う（外の画像は使わない）。台本のナレーション・字幕・作者紹介・使っていく場面は、この DEMO.md から読む（直したら書き出し直すだけでよい）。ナレーションの字幕は `recordings/draft-video.srt` にも出る（録音と YouTube の字幕の下書き）
  - **声**：`recordings/voice/scene1.m4a`（シーンの番号ごと。wav・aiff・mp3 も可）を置くと作者の録音を使う。ないシーンは macOS の読み上げ（`say -v Kyoko -r 178`。作者の速さ1秒に約5.3字に合わせた。`--rate` で変えられる）で仮の声を作る。仮の声は尺を確かめるためのもので、提出版には使わない。仮の声のときは字幕の時刻を声の区切りに合わせ、画面の切り替わりに合わせたい文（`scripts/lib/video-cues.ts` の `ANCHORS`）はその時刻まで待たせる。録音のときは、頭と終わりの無音を切り、声の中の無音を手がかりに字幕の時刻を合わせる（`scripts/lib/align.ts`）。声の大きさは書き出しのときにそろえる（-16 LUFS）。声がシーンの枠からはみ出しそうなときは、書き出しの最後に警告が出る
  - **録音用の原稿**：`npx tsx scripts/make-recording-sheet.ts` で `recordings/recording-sheet/` に作る。シーンごとに枠の秒数・読み終える上限・字数・ファイル名・画面に合わせてあける「間」・読み方を並べる。作者には Artifact で見せる
  - **絵コンテ表**：続けて `npx tsx scripts/make-storyboard.ts` を動かすと、`recordings/storyboard/` に絵コンテ表（シーンごとの時刻・サムネイル・画面・テロップ・ナレーションと声の余り、縮小版の動画）ができる。作者には Artifact（非公開のページ）で見せ、直しを「シーン3」「0:52 の字幕」のように時刻かシーン番号で受け取る（Discord のオフィスアワーの助言）
  - **動く画面を主役に**（2026-11-05 作者の判断。オフィスアワーの助言。主催の案内でも）：名乗りの場面（シーン3の後半）と図（シーン1・2・9）、紙芝居の1コマ（シーン5）のほかは、作品が実際に動く画面にする
- **代替案**：時間や API クレジットが足りないときは、PowerPoint にスクリーンショットと録画を貼り、音声付きで動画に書き出す
- 録画と合成は手元のツールで行うので、API クレジットはほとんど使わない。クレジットを使ったのは、シーン8の収録で Claude を動かした分だけ
