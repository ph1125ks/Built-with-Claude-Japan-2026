## この動画で伝えること

1. **作者は誰か・なぜ作ったか**：病院で抗菌薬の使い方を支える薬剤師。入職2年目に、感染症の専門医がいない病院でそのチーム（AST）を任され、手探りで始めた。現場で見てきたのは、ほとんどの細菌に効く「切り札」の薬が、効いているからと続いてしまうこと。教えても、選ぶ場面では広い薬に手が伸びる。耐性は目に見えにくく、何年もかけて返ってくるから
2. **どれくらい困っているか**：対策をとらなければ、2050年に薬剤耐性による死亡は年間1,000万人、がんを超えるという試算がある
3. **しくみ（すべての人に）**：抗菌薬（いわゆる抗生物質）は細菌を倒す薬。薬ごとに効く細菌が違う。はじめは原因の細菌が分からないので、切り札が選ばれがち。でも薬を使うと、効かない細菌だけが残って増える（選択圧。作者の研究テーマで、ゲームの名前）
4. **どう解決するか**：何年も先の結果を数分で、安全に失敗しながら体験できるタワーディフェンス
5. **Claude の役割**：教える人が地域と教えたいことを入れると、Claude がその地域の公開データでステージを作り、自分で試して直す。数値は作らせない。開発も Claude Code と一緒に行い、薬の値や耐性の速さは、作者が公的な文書と照らして確かめた
6. **これから**：院内の勉強会・実習・講義で使い始め、手探りで始める人にも届ける。いまの一手が、未来をつくる

## 収録の準備

- ゲームは乱数の種（シード）を固定して収録する。同じ操作なら毎回同じ展開になるようにする（SPEC.md「完成の定義」）
- 耐性の進み方（A：薬ごと／B：系統ごと）もURL（`?model=A` か `?model=B`）で固定して収録する。タイトル画面で選んだものはブラウザに覚えるので、固定しないと前に選んだほうで始まる
- プレイの場面は、録画用の操作シナリオ（乱用・適正）で自動再生する。手で遊ぶと尺がぶれるため
  - 乱用（`?auto=demo-abuse`）：ステージ1も2050年も、カルバペネム系を連打する（MEPM。待ち時間中は IPM/CS）。2026-11-04 作者の判断
  - 適正（`?auto=demo-proper`）：グラム陰性桿菌にはまず CTRX、CTRX が効かない大腸菌・肺炎桿菌には CMZ、腸球菌には ABPC、緑膿菌には CAZ。途中で内服 CFDN を1回使う。2026-11-04 作者の判断
  - 種は **570**（`scripts/demo-seeds.ts` で選んだ。乱用はステージ1を膀胱84%で楽勝し、2050年は手札のどれも効かない菌が12%で負ける。適正はステージ1も2050年も守り切る（膀胱 100%／88%）。乱用と適正で同じ種なので、やり直しでも手札がそろう）。`tests/demo.test.ts` がこの展開を確かめる。データやルールを変えてテストが落ちたら、種を選び直す
  - ブラウザでそのまま再生できる：`/?model=A&seed=570&r=1.5&auto=demo-abuse`（適正は `demo-proper`）
- **録画のしかた**（2026-11-04、作者の判断で自動）：開発サーバーを動かしてから `npx tsx scripts/record-demo.ts --take title,abuse,proper --base http://localhost:5173`。画面なしの Chrome で 1920×1080・30fps の MP4 を `recordings/`（Git に入れない）に書き出す。画面が切り替わった時刻は同じ名前の `.json` に残る（編集で切り出す目印）。`title`＝タイトルと遊び方、`abuse`＝乱用の通し（シーン0・5・6）、`proper`＝適正の通し（シーン7）、`intro`＝しくみの見せ方（シーン4）
- 教える側（シーン8）は本物の Claude を動かして収録した。ログを作り物にしない
- **作者の写真**：`recordings/author/photo1.jpg`（シーン1）・`photo2.jpg`（シーン10）。作者が用意した写真（2026-11-05）。Git に入れない。新聞などに載った写真は使わない（著作権がある）
- 字幕は全編につける。ナレーションの文字起こしに加えて、用語の補足を出す（例：「選択圧」「自然耐性」）
- 画面に出る数値は、収録した版のデータのとおりにする。ナレーションに入れる数値は、2050年の試算と作者の「10年」だけ

## 動画の作り方

- **第一案（自動化）**
  1. ブラウザの自動操作でプレイ画面と教員画面を録画する（Claude が用意する）
  2. 作者がこの台本を読み、シーンごとに録音する
  3. スクリプトで録画・字幕・音声をつなぎ、MP4（1920×1080）に書き出す
  4. 作者が確認し、YouTube に限定公開でアップロードして、提出フォームに貼る
- **仮の動画**：`npx tsx scripts/make-draft-video.ts` で、録画（`recordings/`）を台本の時間配分どおりに切り出して早送りし、ナレーションを字幕と声にしてつなぐ。字幕と、コードで描く絵（時間のずれの図・写真の場面）は画面なしの Chrome で描いて重ねる（手元の ffmpeg には文字を描く機能がない）。台本のナレーション・字幕・作者紹介・使っていく場面は、この DEMO.md から読む（直したら書き出し直すだけでよい）。ナレーションの字幕は `recordings/draft-video.srt` にも出る（録音と YouTube の字幕の下書き）
  - **声**：`recordings/voice/scene1.m4a`（シーンの番号ごと。wav・aiff・mp3 も可）を置くと作者の録音を使う。ないシーンは macOS の読み上げ（`say -v Kyoko`）で仮の声を作る。仮の声は尺を確かめるためのもので、提出版には使わない。仮の声のときは字幕の時刻を声の区切りに合わせ、画面の切り替わりに合わせたい文（`scripts/lib/video-cues.ts` の `ANCHORS`）はその時刻まで待たせる。録音のときは、頭と終わりの無音を切り、声の中の無音を手がかりに字幕の時刻を合わせる（`scripts/lib/align.ts`）。声の大きさは書き出しのときにそろえる（-16 LUFS）。声がシーンの枠からはみ出しそうなときは、書き出しの最後に警告が出る
  - **録音用の原稿**：`npx tsx scripts/make-recording-sheet.ts` で `recordings/recording-sheet/` に作る。シーンごとに枠の秒数・読み終える上限・字数・ファイル名・画面に合わせてあける「間」・読み方を並べる。作者には Artifact で見せる
  - **絵コンテ表**：続けて `npx tsx scripts/make-storyboard.ts` を動かすと、`recordings/storyboard/` に絵コンテ表（シーンごとの時刻・サムネイル・画面・テロップ・ナレーションと声の余り、縮小版の動画）ができる。作者には Artifact（非公開のページ）で見せ、直しを「シーン3」「0:52 の字幕」のように時刻かシーン番号で受け取る（Discord のオフィスアワーの助言）
  - **動く画面を主役に**（2026-11-05 作者の判断。オフィスアワーの助言）：写真の場面（シーン1・10の前半）と図（シーン2・3の前半・9）のほかは、作品が実際に動く画面にする
- **代替案**：時間や API クレジットが足りないときは、PowerPoint にスクリーンショットと録画を貼り、音声付きで動画に書き出す
- 録画と合成は手元のツールで行うので、API クレジットはほとんど使わない。クレジットを使ったのは、シーン8の収録で Claude を動かした分だけ
