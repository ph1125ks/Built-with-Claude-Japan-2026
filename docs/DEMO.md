## この動画で伝えること

1. **どれくらい困っているか**：対策をとらなければ、2050年に薬剤耐性による死亡は年間1,000万人、がんを超えるという試算がある
2. **誰の、どんな課題か**：耐性を防ぐ要は抗菌薬の適正使用。でも薬学生や新人の医療者が、それを実践的に学ぶ機会は少ない。作者は病院で抗菌薬の使い方を支える AST の薬剤師
3. **しくみ（すべての人に）**：抗菌薬（いわゆる抗生物質）は細菌を倒す薬。薬ごとに効く細菌が違い、ほとんどに効く「切り札」もある。はじめは原因の細菌が分からないので、切り札が選ばれがち。でも薬を使うと、効かない細菌だけが残って増える（選択圧）
4. **どう解決するか**：選んだ抗菌薬が未来の耐性菌をつくることを、遊びながら体感できるタワーディフェンス
5. **Claude の役割**：教える人が地域の公開データと教えたいことを入れると、Claude がステージを設計し、シミュレーションで自分で確かめて直す。数値は作らせない。プログラムを書けない教員でも、自分の地域の教材を作れる
6. **使い続ける場面**：作者が書く（シーン9）

## すべての人に伝わるように（第3版）

2026-11-05、作者の依頼で、10人の評価役（中学生〜72歳、保護者・外国出身の人・審査員など）に第2版の試作を見せた（[docs/eval/audience/](eval/audience/README.md)）。10人全員が「薬を使うと、効く細菌は倒れ、効かない細菌だけが残って増える（選択圧）」が語られていない点を、いちばんの穴に挙げた。第3版では次のようにした（作者の判断）。

- **「しくみ」の場面（シーン2、30.5秒）を足す**：抗菌薬＝いわゆる抗生物質 → 薬ごとに効く細菌が違い、切り札がある → はじめは細菌が分からず切り札が選ばれがち → 効かない細菌だけが残って増える（選択圧）。画面は「はじめての人へ」のページ（`intro.html?present=1`）の録画
- **声は平易な言葉、専門用語は字幕や画面のかっこに**（言い換えの表は [PLAIN-LANGUAGE.md](PLAIN-LANGUAGE.md)）。声では薬の名前を言わず、「切り札」「その細菌に合う薬」と言う（シーン5の第2版は、7秒に薬の名前が4つで、いちばん伝わらなかった）
- 「AI の Claude」と言う。「27% → 17%」は「切り札を使い続けても守れてしまう割合」と添える
- 締めは、医療アドバイスにせず「なぜ抗菌薬を正しく使うのかを知ることは、抗菌薬を受け取る人の理解にもつながる」（作者の方針）
- 適正の自動操作の動きはそのまま、言い方を「狭い薬へ」から「切り札を使わずに、その細菌に合う薬へ」に（作者の判断）

## 収録の準備

- ゲームは乱数の種（シード）を固定して収録する。同じ操作なら毎回同じ展開になるようにする（SPEC.md「完成の定義」）
- 耐性の進み方（A：薬ごと／B：系統ごと）もURL（`?model=A` か `?model=B`）で固定して収録する。タイトル画面で選んだものはブラウザに覚えるので、固定しないと前に選んだほうで始まる。タイトル画面には選択の欄が、遊んでいる途中の左上には「耐性 A（薬ごと）」などが映る（2026-11-03 から）
- シーン3〜5のプレイは、録画用の操作シナリオ（乱用・適正）で自動再生する。手で遊ぶと尺がぶれるため
  - 乱用（`?auto=demo-abuse`）：ステージ1も2050年も、カルバペネム系を連打する（MEPM。待ち時間中は IPM/CS）。2026-11-04 作者の判断
  - 適正（`?auto=demo-proper`）：グラム陰性桿菌にはまず CTRX、CTRX が効かない大腸菌・肺炎桿菌には CMZ、腸球菌には ABPC、緑膿菌には CAZ。途中で内服 CFDN を1回使う。2026-11-04 作者の判断
  - 種は **570**（`scripts/demo-seeds.ts` で選んだ。乱用はステージ1を膀胱84%で楽勝し、2050年は手札のどれも効かない菌が12%で負ける（2026-11-04 に耐性モデル A の係数を変えたあとの値。同じ日に情報の距離（菌名 0.8333・感受性 0.6667）を変えたあとも同じ）。適正はステージ1も2050年も守り切る（情報の距離を変えたあとは膀胱 100%／88%）。乱用と適正で同じ種なので、やり直しでも手札がそろう）。`tests/demo.test.ts` がこの展開を確かめる。データやルールを変えてテストが落ちたら、種を選び直す
  - ブラウザでそのまま再生できる：`/?model=A&seed=570&r=1.5&auto=demo-abuse`（適正は `demo-proper`）
- **録画のしかた**（2026-11-04、作者の判断で自動）：開発サーバーを動かしてから `npx tsx scripts/record-demo.ts --take title,abuse,proper --base http://localhost:5173`。画面なしの Chrome で 1920×1080・30fps の MP4 を `recordings/`（Git に入れない）に書き出す。画面が切り替わった時刻は同じ名前の `.json` に残る（編集で切り出す目印）。`title`＝タイトルと遊び方、`abuse`＝乱用の通し（シーン0・2・3・4）、`proper`＝適正の通し（シーン5）

- 字幕は全編につける。ナレーションの文字起こしに加えて、用語の補足を出す（例：「選択圧」「自然耐性」）

## 動画の作り方

- **第一案（自動化）**
  1. ブラウザの自動操作でプレイ画面と教員画面を録画する（Claude が用意する）
  2. 作者がこの台本を読み、シーンごとに録音する
  3. スクリプトで録画・字幕・音声をつなぎ、MP4（1920×1080）に書き出す
  4. 作者が確認し、YouTube に限定公開でアップロードして、提出フォームに貼る
- **仮の動画**（2026-11-04、2026-11-05 に声と絵コンテ表を足した）：`npx tsx scripts/make-draft-video.ts` で、録画（`recordings/`）を台本の時間配分どおりに切り出して早送りし、ナレーションを字幕と声にしてつなぐ（2:59）。字幕は画面なしの Chrome で描いて重ねる（手元の ffmpeg には文字を描く機能がない）。台本のナレーション・字幕・作者紹介は、この DEMO.md から読む（直したら書き出し直すだけでよい）。ナレーションの字幕は `recordings/draft-video.srt` にも出る（録音と YouTube の字幕の下書き）
  - **声**：`recordings/voice/scene1.wav`（シーンの番号ごと。m4a・aiff・mp3 も可）を置くと作者の録音を使う。ないシーンは macOS の読み上げ（`say -v Kyoko`）で仮の声を作る。仮の声は尺を確かめるためのもので、提出版には使わない。仮の声のときは字幕の時刻を声の区切りに合わせ、画面の切り替わりに合わせたい文（シーン3の「ところが結果を見ると」、シーン4の「手札の薬が」、シーン5の「今度は2050年も守り切れました」。`scripts/lib/video-cues.ts` の `ANCHORS`）はその時刻まで待たせる。録音のときは、頭と終わりの無音を切り、声の中の無音を手がかりに字幕の時刻を合わせる（`scripts/lib/align.ts`：どの無音を区切りにすると、各字幕の話す長さが声になる字の量に最もよく合うかを全体で選ぶ）。声の大きさは書き出しのときにそろえる（-16 LUFS）。声がシーンの枠からはみ出しそうなときは、書き出しの最後に警告が出る
  - **録音用の原稿**（2026-11-05）：`npx tsx scripts/make-recording-sheet.ts` で `recordings/recording-sheet/` に作る。シーンごとに枠の秒数・読み終える上限・字数・ファイル名・画面に合わせてあける「間」（シーン3は約4秒、シーン4は約1秒、シーン5は約3.5秒。1秒に5字で読んだときの計算）・読み方を並べる。作者には Artifact で見せる
  - **絵コンテ表**：続けて `npx tsx scripts/make-storyboard.ts` を動かすと、`recordings/storyboard/` に絵コンテ表（シーンごとの時刻・サムネイル・画面・テロップ・ナレーションと声の余り、縮小版の動画）ができる。作者には Artifact（非公開のページ）で見せ、直しを「シーン3」「0:52 の字幕」のように時刻かシーン番号で受け取る（Discord のオフィスアワーの助言）
  - **動く画面を主役に**（2026-11-05 作者の判断。オフィスアワーの助言に沿って、作品が実際に動く画面を中心にする）：シーン1・8はタイトル画面の後ろで適正ボットが遊ぶデモの録画（`title` の録画はタイトル画面を40秒映す）。シーン6は、作業の記録を約1.33倍にして左に寄せ（右に工程の図と直した数字）、できたステージと QR を1.5倍に切り出して見せる（第2版。約1.8倍だと右の図が記録の文を隠した）
- **代替案**：時間や API クレジットが足りないときは、PowerPoint にスクリーンショットと録画を貼り、音声付きで動画に書き出す
- 録画と合成は手元のツールで行うので、API クレジットはほとんど使わない。クレジットを使うのは、シーン6の収録で Claude を動かす分だけ

## 審査の観点との対応

| 観点 | 動画のどこで見せるか |
|---|---|
| インパクト（30%） | シーン0（どれくらい困っているか）、シーン1（作者自身の現場から出た課題）、シーン5（耐性菌の怖さの実感）、シーン7・9（誰がどこで使い続けるか） |
