# tests/ の一覧

Vitest の単体テスト。`npm test` で全部動く（139 件、約2秒。GitHub Actions でも push のたびに動く）。どれもブラウザなしで動く（描画は `src/game/`、テストの対象はエンジン `src/engine/` と、データ・ページの決まり）。エンジン・テスト・データを編集すると、フック（`.claude/hooks/test-engine.sh`）が自動で走らせる。

| ファイル | 何を確かめるか |
|---|---|
| `data.test.ts` | 公開データの取り込み（年報の値と一致：全国の大腸菌の CTRX 感性率 68.1% など）、効く確率の決め方、医療費（薬価の段階化）、公的な文書に沿った設定（投与回数・吸収率・AWaRe 分類） |
| `game.test.ts` | エンジンの本体：召喚と投与間隔、効く・効かない（自然耐性・代用）、情報の見え方（距離で明らかになる）、勝敗、同じ種なら同じ結果 |
| `resistance.test.ts` | 耐性モデル A（選択圧の再現）と B（耐性ゲージ）、未来ステージ（2050年）への引き継ぎ、ESBL・CRE の連動 |
| `shortage.test.ts` | 供給制限（遊ぶたびに手札の何枚かが使えない。種で決まる） |
| `bots.test.ts` | ボットが見える情報だけで判断すること、ボットの強さの順序（適正 > ランダム > 何もしない）、速さ |
| `ahi.test.ts` | 系統の使い分けの指標（AHI）の式 |
| `stagecheck.test.ts` | ステージの合格の検査（SPEC.md 5.4）：文章の決まり（使わない語・投与量・診療の指示に読める文を止める）、手札の効き目、シミュレーションによる合格の目安。教員モードで Claude が作った案も同じ検査を通る |
| `stages.test.ts` | 同梱のステージ（`data/stages/`）と、教員モードで承認して書き出したステージ（`public/stages/`）が検査を通ること |
| `demo.test.ts` | 録画用の自動操作のシナリオ：乱用はカルバペネム系だけでステージ1に勝ち 2050年に負ける、適正は両方守り切る（台本の流れ） |
| `format.test.ts` | カードの表示（用量は出さない：SPEC.md 7.1）、スペクトラムの目安、数字キーの割り当て、1% 未満の耐性率を 0% に見せない |
| `pixel.test.ts`・`soldiers.test.ts` | ドット絵の兵士と細菌（作風・濃さ・系統ごとの姿）、外部の素材を使っていないこと |
| `intro.test.ts` | 「はじめての人へ」のページ：前提の鎖の文（`docs/PLAIN-LANGUAGE.md`）のままか、表がデータから作られるか、選択圧の動く絵、動画用の時刻表 |
| `replay.test.ts` | 作業の記録の再生ページ：時刻表、`?log=` の値の検査（`public/replays/` の中だけ）、記録の読み込み |
| `bugs.test.ts` | 試遊で見つけた不具合の再発防止（盤面の札、手札の補助） |

医学データそのものの点検は、テストとは別に `npm run data:verify`（元の表との照合）とサブエージェント `data-auditor` で行う。
