# JANIS と薬価の取り込み

ゲームの感受性率・菌の出現割合・医療費は、公開データから作っている。年に一度（JANIS の年報は例年8月ごろ、薬価は4月改定）、この手順で取り込み直す。

## いまの取得元

`scripts/data/sources.ts` にまとめてある。

| データ | 取得元 |
|---|---|
| 感受性（全国） | e-Stat「院内感染対策サーベイランス」2025年年報 statInfId=000040494034 |
| 感受性（近畿7府県） | 同 近畿 statInfId=000040494039 |
| 薬価 | 厚労省「薬価基準収載品目リスト（令和8年11月1日適用）」注射薬・内用薬 |

- JANIS のサイトは 2026-10-27 から停止中。e-Stat に同じ年報が Excel で載っている
- 年報の判定基準は CLSI 2012（入院検体）

## 手順

1. 新しい年報・薬価リストの URL を調べ、`scripts/data/sources.ts` を書き換える（ファイル名・URL・表題）
   - e-Stat の statInfId は年ごとに変わる。地域ブロック別のファイルは別の statInfId
   - 出力ファイル名（`janis-2025.json` など）を変える場合は `scripts/data/extract.ts` と `src/engine/data.ts` の import も直す
2. `npm run data:fetch` で元の Excel を `data/raw/` に取る（`data/raw/` はコミットしない）
3. シートの名前や列の並びが変わっていないか、`node -e` で数行表示して確かめる
   - 感受性のシート：「7.主要菌の抗菌薬感受性(全体)」。列は 菌種名・抗菌薬名・合計・S・SorI・I・IorR・R・NS・判定不能 の株数、その後に割合（地域ブロック別は先頭に都道府県の列）
   - 尿の分離菌のシート：「3.検査材料別分離菌数割合(尿)(全体)」。3列目が重複処理後の株数
   - 薬価リスト：3列目が成分名、4列目が規格、11列目が先発品の印、13列目が薬価
4. `npm run data:build` で `data/generated/` を作り直す。表示される大腸菌の感性率と1日薬価が、元の表と合っているか目で確かめる
5. `npm run data:verify` で照合する。「値がない組み合わせ」が出たら、`data/rules.json` の proxies で扱いを決める（作者の監修が要る）
6. `npm test` を通す。年報の値を直接確かめているテスト（`tests/data.test.ts`）は、新しい年報の値に書き換える
7. `data/README.md` の出典・取得日と、`docs/DEVLOG.md` に、何を取り込み直したかを書く

## 守ること

- 割合は丸めた値を使わず、株数から計算する（`src/engine/susceptibility.ts`）
- 菌×薬の「効く確率」の変換ルール（S のみ、など）は `data/rules.json` にあり、作者の監修で決まる。勝手に変えない
- 製品名（商標）はゲームに出さない。薬価は代表の値（いまは同じ規格の最小値）を使う
- 元の Excel（`data/raw/`）はコミットしない。出典の書き方は `data/README.md` に従う
